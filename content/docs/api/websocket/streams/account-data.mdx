---
title: Account Data Streams
description: Real-time subaccount positions, orders, trades, balances, and portfolio streams.
---

Real-time subaccount-level activity. Subscriptions must be scoped to a specific `subaccount` or `wallet` address.

> In all examples below, replace `{SUBACCOUNT_ADDRESS}` with your subaccount address in DeepX and `{WALLET_ADDRESS}` with your wallet address (e.g., `{WALLET_ADDRESS}`).

## Push Behavior

- **On subscribe**: the server immediately pushes the current state as a raw array. There are no pagination wrappers (`hasNext`, `pageNo`, etc.).
- **On change**: the server pushes only the changed or newly created item as a single object.

Clients should initialize local state from the snapshot and apply individual updates as they arrive.

## 1. Perpetual Positions (`account@perp-positions`)

Pushes position state whenever size, entry price, or unrealized PnL changes.

**Channel**: `account@perp-positions`
**Scope**: `subaccount` (required) — positions are per subaccount, not per wallet

**Subscribe**:
```json
{
  "method": "subscribe",
  "id": "req-10",
  "params": {
    "channel": "account@perp-positions",
    "subaccount": "{SUBACCOUNT_ADDRESS}"
  }
}
```

**Initial snapshot** (array):
```json
{
  "channel": "account@perp-positions",
  "data": [
    {
      "symbol": "ETH-USDC",
      "subaccount": "{SUBACCOUNT_ADDRESS}",
      "side": "BUY",
      "qty": "0.01",
      "entryPrice": "2025.48",
      "effectiveLeverage": "10",
      "liqPrice": "1850.00",
      "unrealizedPnl": "12.50",
      "fundingPayment": "-0.138",
      "takeProfit": null,
      "stopLoss": null,
      "time": 1713800000000,
      "updatedTime": 1713825891591
    }
  ]
}
```

The initial snapshot contains open positions only (`qty` greater than zero). If your subaccount has no open positions, `data` is an empty array:

```json
{
  "channel": "account@perp-positions",
  "data": []
}
```

Use the snapshot as your complete current position list. In particular, replace any previously stored positions with an empty list when `data` is `[]`. `data` is always an array for an initial snapshot; it is never `null` or an object.

**Incremental update** (single object):
```json
{
  "channel": "account@perp-positions",
  "data": {
    "symbol": "ETH-USDC",
    "subaccount": "{SUBACCOUNT_ADDRESS}",
    "side": "BUY",
    "qty": "0.01",
      "entryPrice": "2025.48",
      "effectiveLeverage": "10",
      "liqPrice": "1850.00",
      "unrealizedPnl": "13.82",
    "fundingPayment": "-0.139",
    "takeProfit": null,
    "stopLoss": null,
    "time": 1713800000000,
    "updatedTime": 1713825921591
  }
}
```

| Field | Type | Description |
|---|---|---|
| `symbol` | string | Perpetual market symbol |
| `subaccount` | string | Subaccount address |
| `side` | `"BUY"` \| `"SELL"` | Position direction (`BUY` = long, `SELL` = short) |
| `qty` | string | Current position size in base asset. `"0"` indicates that the position has closed |
| `entryPrice` | string | Average entry price |
| `effectiveLeverage` | string | Effective leverage cap in effect for this position |
| `liqPrice` | string | Estimated liquidation price |
| `unrealizedPnl` | string | Floating PnL at current mark price |
| `fundingPayment` | string | Cumulative funding payments for this position lifecycle |
| `takeProfit` | string \| null | Take-profit trigger price, if set |
| `stopLoss` | string \| null | Stop-loss trigger price, if set |
| `time` | int64 | Position open time (epoch ms) |
| `updatedTime` | int64 | Last state change timestamp (epoch ms) |

**When a position closes**: After a position is fully closed, including through liquidation, you receive one position update with `qty: "0"`. Remove the position identified by `subaccount` and `symbol` from your local list. A `qty: "0"` update can be the last update you receive after closing your final position; do not wait for an empty array. An empty array is only an initial snapshot.

The update preserves the position's `side`, `entryPrice`, `effectiveLeverage`, and opening `time`. `fundingPayment` is its final cumulative value and `updatedTime` is the close time. As the position is no longer open, `unrealizedPnl` and `liqPrice` are `"0"`, and `takeProfit` and `stopLoss` are `null`.

**Incremental update** (fully closed position):
```json
{
  "channel": "account@perp-positions",
  "data": {
    "symbol": "ETH-USDC",
    "subaccount": "{SUBACCOUNT_ADDRESS}",
    "side": "BUY",
    "qty": "0",
    "entryPrice": "2025.48",
    "effectiveLeverage": "10",
    "liqPrice": "0",
    "unrealizedPnl": "0",
    "fundingPayment": "-0.139",
    "takeProfit": null,
    "stopLoss": null,
    "time": 1713800000000,
    "updatedTime": 1713825951591
  }
}
```

See [`PerpPosition`](/api/rest/account/getPerpPositions) for the shared field reference. Zero-quantity updates apply only to this WebSocket stream. Initial snapshots and REST position lists contain open positions only.

## 6. Account Balances (`account@balances`)

Per-asset net balances for a subaccount. Pushes on any balance-affecting event: deposit, withdrawal, borrow, repayment, settlement, liquidation, or funding payment.

For the full history of what caused each change, use the REST endpoint `GET /v1/account/subaccounts/{address}/balance-events`.

**Channel**: `account@balances`
**Scope**: `subaccount` (required — balances are per subaccount)

**Subscribe**:
```json
{
  "method": "subscribe",
  "id": "req-15",
  "params": {
    "channel": "account@balances",
    "subaccount": "{SUBACCOUNT_ADDRESS}"
  }
}
```

**Initial snapshot** (array of all asset balances):
```json
{
  "channel": "account@balances",
  "data": [
    {
      "asset": "USDC",
      "balance": "799.80",
      "price": "1.0"
    },
    {
      "asset": "ETH",
      "balance": "0.500",
      "price": "2034.75"
    }
  ]
}
```

**Incremental update** (single asset entry when its balance changes):
```json
{
  "channel": "account@balances",
  "data": {
    "asset": "USDC",
    "balance": "-20.00",
    "price": "1.0"
  }
}
```

| Field | Type | Description |
|---|---|---|
| `asset` | string | Token symbol (e.g., `"USDC"`) |
| `balance` | string | Net balance. Positive = holds asset. Negative = owes asset (from borrow or trading loss) |
| `price` | string | Current index price in USDC per unit of the asset |

## 7. Portfolio Summary (`account@portfolio`)

Unified subaccount metrics. Account-level values are denominated in USDC. Balance and transfer-limit expansions are optional; account risk calculations always include the complete subaccount.

**Channel**: `account@portfolio`
**Scope**: `subaccount` (required)

**Subscribe (summary only)**:
```json
{
  "method": "subscribe",
  "id": "req-16",
  "params": {
    "channel": "account@portfolio",
    "subaccount": "{SUBACCOUNT_ADDRESS}"
  }
}
```

**Subscribe (selected expansions)**:
```json
{
  "method": "subscribe",
  "id": "req-17",
  "params": {
    "channel": "account@portfolio",
    "subaccount": "{SUBACCOUNT_ADDRESS}",
    "include": ["balances", "transferLimits"],
    "assets": ["ETH", "USDC"],
    "autoBorrow": true
  }
}
```

`include` supports `balances` and `transferLimits`. `assets` filters only the requested expansion and never narrows account-level risk calculations. Omitting `assets` includes all non-zero assets; an explicit asset list may include zero balances. `autoBorrow` defaults to false and controls how included `transferLimits` are calculated: false bounds `maxTransferableQty` by the asset's account balance; true may include an amount that creates new debt. Invalid assets, include values, or non-boolean `autoBorrow` values are rejected.

**Push payload**:
```json
{
  "channel": "account@portfolio",
  "data": {
    "subaccount": "{SUBACCOUNT_ADDRESS}",
    "valuationAsset": "USDC",
    "equity": "799.80",
    "totalDepositsUsd": "799.80",
    "totalBorrowsUsd": "0.00",
    "totalCollateral": "800.19",
    "initCollateral": "800.19",
    "maintMarginReq": "0.41",
    "initMarginReq": "32.01",
    "availableMargin": "768.18",
    "uniMMR": "16.68",
    "uniIMR": "25.00",
    "balances": [{"asset": "USDC", "balance": "779.80", "price": "1.00"}],
    "transferLimits": [{"asset": "USDC", "autoBorrow": false, "status": "AVAILABLE", "maxTransferableQty": "768.18"}],
    "time": 1713825891591
  }
}
```

`balances` and `transferLimits` are returned only when requested through `include`. Balance quantities and transfer limits use the asset's own unit; prices and account-level amounts use USDC.

`maxTransferableQty` is calculated while retaining current positions, orders, and debt. It reflects the subscription's `autoBorrow` option, echoed in each transfer-limit object. Limits for different assets share the same account margin capacity and must not be added together. The limit is recalculated when a transfer or withdrawal is submitted.

A requested asset whose limit fails keeps its entry with `status: UNAVAILABLE` rather than being omitted. See [`AccountTransferLimit`](/api/rest/account/getSubaccountTransferLimit) for the field reference, including `status` semantics and null vs `"0"`.

`uniMMR` and `uniIMR` are unitless and are `null` when their corresponding margin requirement is zero.

**Update behavior**: Each message is a complete snapshot for the requested view. Updates may be combined, so clients should replace the previous snapshot. Reconnecting and subscribing again returns a new snapshot.

**REST equivalent**: `GET /v1/account/subaccounts/{address}/portfolio` accepts the same `include`, `assets`, and `autoBorrow` parameters (as query parameters). For one asset, `GET /v1/account/subaccounts/{address}/transfer-limits/{asset}` returns the same transfer-limit object.
