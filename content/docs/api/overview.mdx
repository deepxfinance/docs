**Current API Version:** `1.3.0`

## Known Limitations

**Values in API responses are not guaranteed to reflect the same chain block.** This applies whenever a single response combines values from different sources (e.g. account portfolio endpoints such as `GET /v1/account/subaccounts/{address}/portfolio`), and equally to values fetched across separate requests. Fields may therefore be mutually inconsistent — combinations that never existed on any single block are possible. In addition, the `time` field is the server wall-clock time at response assembly, not the timestamp of any block the data belongs to. Do not derive liquidation or risk decisions from fields assuming they are mutually consistent.

## Changelog

### v1.3.0 (2026-09-20)

- Made `uniMMR` and `uniIMR` nullable when the corresponding margin requirement is zero.
- Renamed `maxWithdrawQty` to `maxWithdrawableQty`.
- Simplified withdrawal-limit status to `AVAILABLE` and `UNAVAILABLE`.

### v1.2.0 (2026-09-15)

- Added optional portfolio expansions for balances and per-asset withdrawal limits.
- Added asset filtering and the single-asset withdrawal-limit endpoint.
- Standardized account valuation amounts and asset prices as USDC-denominated.

### v1.1.0 (2026-06-13)

- Added cross-chain balance event support.
- Standardized EVM address naming and decimal financial fields.

### v1.0.0 (2026-03-24)

- Initial release.
