---
title: Account Data Streams
description: Real-time subaccount positions, orders, trades, balances, and portfolio streams.
---

Real-time subaccount-level activity. Subscriptions must be scoped to a specific `subaccount` or `wallet` address.

> In all examples below, replace `{SUBACCOUNT_ADDRESS}` with your subaccount address in DeepX and `{WALLET_ADDRESS}` with your wallet address (e.g., `{WALLET_ADDRESS}`).

## Push Behavior

- **On subscribe**: the server immediately pushes the current state as a raw array. There are no pagination wrappers (`hasNext`, `pageNo`, etc.).
- **On change**: the server pushes only the changed or newly created item as a single object.

Clients should initialize local state from the snapshot and apply individual updates as they arrive.

## 1. Perpetual Positions (`account@perp-positions`)

Pushes position state whenever size, entry price, or unrealized PnL changes.

**Channel**: `account@perp-positions`
**Scope**: `subaccount` (required) — positions are per subaccount, not per wallet

**Subscribe**:
```json
{
  "method": "subscribe",
  "id": "req-10",
  "params": {
    "channel": "account@perp-positions",
    "subaccount": "{SUBACCOUNT_ADDRESS}"
  }
}
```

**Initial snapshot** (array):
```json
{
  "channel": "account@perp-positions",
  "data": [
    {
      "symbol": "ETH-USDC",
      "subaccount": "{SUBACCOUNT_ADDRESS}",
      "side": "BUY",
      "qty": "0.01",
      "entryPrice": "2025.48",
      "effectiveLeverage": "10",
      "liqPrice": "1850.00",
      "unrealizedPnl": "12.50",
      "fundingPayment": "-0.138",
      "takeProfit": null,
      "stopLoss": null,
      "time": 1713800000000,
      "updatedTime": 1713825891591
    }
  ]
}
```

**Incremental update** (single object):
```json
{
  "channel": "account@perp-positions",
  "data": {
    "symbol": "ETH-USDC",
    "subaccount": "{SUBACCOUNT_ADDRESS}",
    "side": "BUY",
    "qty": "0.01",
      "entryPrice": "2025.48",
      "effectiveLeverage": "10",
      "liqPrice": "1850.00",
      "unrealizedPnl": "13.82",
    "fundingPayment": "-0.139",
    "takeProfit": null,
    "stopLoss": null,
    "time": 1713800000000,
    "updatedTime": 1713825921591
  }
}
```

| Field | Type | Description |
|---|---|---|
| `symbol` | string | Perpetual market symbol |
| `subaccount` | string | Subaccount address |
| `side` | `"BUY"` \| `"SELL"` | Position direction (`BUY` = long, `SELL` = short) |
| `qty` | string | Current position size in base asset |
| `entryPrice` | string | Average entry price |
| `effectiveLeverage` | string | Effective leverage cap in effect for this position |
| `liqPrice` | string | Estimated liquidation price |
| `unrealizedPnl` | string | Floating PnL at current mark price |
| `fundingPayment` | string | Cumulative funding payments for this position lifecycle |
| `takeProfit` | string \| null | Take-profit trigger price, if set |
| `stopLoss` | string \| null | Stop-loss trigger price, if set |
| `time` | int64 | Position open time (epoch ms) |
| `updatedTime` | int64 | Last state change timestamp (epoch ms) |

## 6. Account Balances (`account@balances`)

Per-asset net balances for a subaccount. Pushes on any balance-affecting event: deposit, withdrawal, borrow, repayment, settlement, liquidation, or funding payment.

For the full history of what caused each change, use the REST endpoint `GET /v1/account/subaccounts/{address}/balance-events`.

**Channel**: `account@balances`
**Scope**: `subaccount` (required — balances are per subaccount)

**Subscribe**:
```json
{
  "method": "subscribe",
  "id": "req-15",
  "params": {
    "channel": "account@balances",
    "subaccount": "{SUBACCOUNT_ADDRESS}"
  }
}
```

**Initial snapshot** (array of all asset balances):
```json
{
  "channel": "account@balances",
  "data": [
    {
      "asset": "USDC",
      "balance": "799.80",
      "price": "1.0"
    },
    {
      "asset": "ETH",
      "balance": "0.500",
      "price": "2034.75"
    }
  ]
}
```

**Incremental update** (single asset entry when its balance changes):
```json
{
  "channel": "account@balances",
  "data": {
    "asset": "USDC",
    "balance": "-20.00",
    "price": "1.0"
  }
}
```

| Field | Type | Description |
|---|---|---|
| `asset` | string | Token symbol (e.g., `"USDC"`) |
| `balance` | string | Net balance. Positive = holds asset. Negative = owes asset (from borrow or trading loss) |
| `price` | string | Current index price in USDC per unit of the asset |

## 7. Portfolio Summary (`account@portfolio`)

Unified subaccount metrics. Account-level values are denominated in USDC. Balance and withdrawal-limit expansions are optional; account risk calculations always include the complete subaccount.

**Channel**: `account@portfolio`
**Scope**: `subaccount` (required)

**Subscribe (summary only)**:
```json
{
  "method": "subscribe",
  "id": "req-16",
  "params": {
    "channel": "account@portfolio",
    "subaccount": "{SUBACCOUNT_ADDRESS}"
  }
}
```

**Subscribe (selected expansions)**:
```json
{
  "method": "subscribe",
  "id": "req-17",
  "params": {
    "channel": "account@portfolio",
    "subaccount": "{SUBACCOUNT_ADDRESS}",
    "include": ["balances", "withdrawalLimits"],
    "assets": ["ETH", "USDC"]
  }
}
```

`include` supports `balances` and `withdrawalLimits`. `assets` filters only the requested expansion and never narrows account-level risk calculations. Omitting `assets` includes all non-zero assets; an explicit asset list may include zero balances. Invalid assets or include values are rejected.

**Push payload**:
```json
{
  "channel": "account@portfolio",
  "data": {
    "subaccount": "{SUBACCOUNT_ADDRESS}",
    "valuationAsset": "USDC",
    "equity": "799.80",
    "totalDepositsUsd": "799.80",
    "totalBorrowsUsd": "0.00",
    "totalCollateral": "800.19",
    "initCollateral": "800.19",
    "maintMarginReq": "0.41",
    "initMarginReq": "32.01",
    "availableMargin": "768.18",
    "uniMMR": "16.68",
    "uniIMR": "25.00",
    "balances": [{"asset": "USDC", "balance": "779.80", "price": "1.00"}],
    "withdrawalLimits": [{"asset": "USDC", "maxWithdrawQty": "768.18", "status": "AVAILABLE", "reasons": []}],
    "time": 1713825891591
  }
}
```

`balances` is present only when requested with `include=balances`; `withdrawalLimits` is present only when requested with `include=withdrawalLimits`. `balance` and `maxWithdrawQty` use the asset's own unit. `price` is USDC per asset unit. Account valuation, collateral, margin requirements, and `availableMargin` use USDC.

`maxWithdrawQty` is the maximum existing deposit quantity withdrawable to the wallet while retaining current positions, orders, and debt. It does not borrow, cancel orders, or close positions. Asset limits are conditional alternatives sharing the same account margin capacity; they must not be added together.

`uniMMR` and `uniIMR` are unitless ratios. When the corresponding margin requirement is zero, the value is `null`, not `"0"`.

Ratios follow [MarginRatio](../../schemas/MarginRatio.yaml) in both the initial
snapshot and subsequent updates. Null means no margin requirement, including
0/0; it is not a liquidation signal. A positive requirement with zero collateral
returns `"0"`. Clients must preserve null rather than convert it to zero or
infinity. Failed calculations are errors, not null-valued successful snapshots.

**Update behavior**: The initial push and every subsequent push are complete snapshots for the requested view. A snapshot is refreshed when balances, orders, positions, prices, interest, funding, risk parameters, account restrictions, pool status, or pool liquidity changes the selected values. Balance changes alone are not the only trigger.

All fields in one snapshot share the same source state and `time`; clients should replace the complete local view. The server may coalesce intermediate states and does not promise one message per chain event. Re-subscription after disconnect returns a complete snapshot.

**REST equivalent**: `GET /v1/account/subaccounts/{address}/portfolio` accepts the same `include` and `assets` query parameters. For one asset, `GET /v1/account/subaccounts/{address}/withdrawal-limits/{asset}` returns the same withdrawal-limit object.
