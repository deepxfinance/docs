---
title: Transaction Nonces and Replacement
---

DeepX has two transaction nonce schemes. The operation being signed determines which scheme applies.

## Sequential Transaction Nonces

A sequential transaction nonce is an account counter. It must equal the nonce account's current value when the transaction executes, then advances by one. A later sequential nonce can be submitted in advance, but waits for its predecessor.

This scheme is used by signed operations that are not designated as timestamp transactions, including general EVM and precompile calls outside trading flows.

## Timestamp Transaction Nonces

Trading and order-management operations use a Unix epoch millisecond timestamp as their transaction nonce. Timestamp nonces do not need to be consecutive.

At block time `T`, the nonce must be strictly inside this window:

```text
T - 1 hour < nonce < T + 1 hour
```

The protocol retains the highest accepted timestamp nonces for each nonce account. A nonce must be unused; once the retained set is full, it must also be greater than the set's lowest value. The retained count is 100 on testnet and 400 on the development network. Generate a fresh current timestamp nonce for each transaction and do not reuse past values.

## Nonce Account Scope

For a direct transaction, the nonce account is the signer. For an authorized delegate transaction targeting a subaccount, the nonce account is the subaccount authority. The authority and all of its authorized delegates therefore share nonce state for that subaccount's transactions and must coordinate their nonce allocation.

A delegate transaction without a subaccount target uses the delegate's own nonce account. In particular, a delegate's [No-Op transaction](/protocol/no-op-transactions) cannot replace that delegate's pending subaccount order, because the two transactions use different nonce accounts.

## Replace a Pending Timestamp Transaction

A No-Op transaction using the same nonce account and timestamp nonce can replace a pending timestamp transaction. This only works while the original transaction remains pending. Once either transaction is finalized, the nonce is consumed and cannot be reused.

See [No-Op Transactions](/protocol/no-op-transactions) for the replacement workflow and [Order Transaction Nonces and Order IDs](/protocol/transaction-nonce-order-ids) for the special relationship between direct order placement and order IDs.
